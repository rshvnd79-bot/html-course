فلش‌کارت — ریزنکات این بخش

DOCTYPE امروز چه نقشی دارد؟یک سوییچ، نه یک نسخه
  • node ۱: <!DOCTYPE html> دیگر نسخهٔ HTML را اعلام نمی‌کند؛ فقط مرورگر را به «حالت استاندارد» می‌برد.
  • بدون آن، مرورگر ممکن است وارد «quirks mode» شود و برخی رفتارهای تاریخی، از جمله تفاوت‌های مدل جعبه، فعال شوند.
  • برای آموزش دقیق‌تر، تفاوت مدل جعبه را به‌صورت تاریخی بررسی کن؛ این رفتار برای همهٔ عناصر و همهٔ شرایط یکسان نیست.
  • پس هر اختلاف ظاهری عجیب در مرورگرهای قدیمی را اول با نبود DOCTYPE بررسی کن.
مقادیر مجاز lang چه هستند؟از BCP 47 استفاده کن
  • زبان با کد زبان و در صورت نیاز کد منطقه نوشته می‌شود: fa، fa-IR، en-US.
  • fa-IR زبان فارسی با منطقهٔ ایران را دقیق‌تر توصیف می‌کند؛ اینکه تلفظ چگونه انجام شود به مرورگر، سیستم‌عامل و موتور تبدیل متن به گفتار بستگی دارد.
  • برای بخش لاتین داخل صفحه فارسی، lang="en" را روی همان عنصر بگذار.
  • attr q: تفاوت lang و xml:lang — در HTML5 فقط lang لازم است.

فلش‌کارت — ریزنکات این بخش

strong و b واقعاً چه تفاوتی دارند؟معنا در برابر ظاهر
  • strong اهمیت زیاد را در معنا مشخص می‌کند؛ نحوهٔ اعلام آن توسط فناوری کمکی می‌تواند متفاوت باشد.
  • b برای جلب توجه بدون انتقال اهمیت ویژه به‌کار می‌رود؛ اگر صرفاً ظاهر می‌خواهی، CSS انتخاب بهتری است.
  • em تأکید در جمله است و لحن را عوض می‌کند: «من این را نگفتم».
  • i برای اصطلاح بیگانه یا فنی است، مثل نام لاتین یک گونه.
del و ins چه زمانی درست پیاده می‌شوند؟تغییرات نسخه‌ای
  • del متن حذف‌شده و ins متن افزوده‌شده را نشان می‌دهند.
  • هر دو datetime و cite می‌پذیرند تا زمان و منبع تغییر ثبت شود.
  • در متن حقوقی یا نسخهٔ سند، این دو با رنگ و خط‌خوردگی معنا را می‌رسانند.
  • به‌جای دوتایی‌کردن متن با رنگ، از همین تگ‌ها استفاده کن.
blockquote و q چه فرقی دارند؟بلوکی در برابر درون‌خطی
  • blockquote نقل‌قول بلوکی است و معمولاً تودرتویی/تورفتگی می‌گیرد.
  • q نقل‌قول کوتاه درون‌خطی است و مرورگر خودش گیومه اضافه می‌کند.
  • منبع نقل‌قول را در cite بگذار؛ خودِ عنصر cite باید نام اثر باشد، نه آدرس.
  • اگر فقط متن کج و گیومه می‌خواهی، متن سادهٔ داخل p کافی است.
time، abbr و dfn را چرا بنویسیم؟قابل فهم برای ماشین و انسان
  • time datetime="2024-05-01" تاریخ خوانا برای ماشین می‌سازد.
  • abbr title="HyperText Markup Language" مخفف را برای صفحه‌خوان باز می‌کند.
  • dfn جای تعریف اصطلاح است و با اولین کاربرد آن می‌آید.
  • این‌ها به سئو و دسترس‌پذیری همزمان کمک می‌کنند.
sub، sup، wbr و br کجا؟کنترل دقیق متن
  • sub پایین‌نویس (H₂O) و sup بالانویس (۲³) است.
  • wbr نقطهٔ شکست اختیاری در کلمات بلند است، مثل exampledomain.com.
  • br فقط شکست خط در متن‌هایی مثل آدرس یا شعر است، نه برای فاصلهٔ چیدمانی.
  • برای فاصله از CSS margin استفاده کن، نه چند br پشت‌هم.

    فلش‌کارت — ریزنکات این بخش

    scope دقیقاً چه چیزی را حل می‌کند؟اتصال سرستون به داده
    • صفحه‌خوان هنگام خواندن هر سلول می‌گوید «دوره: Front-end، سال: ۱۴۰۳».
    • scope="col" برای th ستونی و scope="row" برای th سطری است.
    • در جدول‌های پیچیده یا thهای متعدد، headers و id جایگزین دقیق‌تری است.
    • سلول خالی را با   پر نکن؛ اگر داده ندارد، خالی بگذار یا با CSS مدیریت کن.
    colspan و rowspan چه زمانی لازم‌اند؟ادغام سلول‌ها
    • colspan="2" سلول را روی دو ستون بسط می‌دهد.
    • rowspan همین کار را برای سطرها انجام می‌دهد.
    • اگر ساختار جدول را با ادغام بی‌دلیل خراب کنی، صفحه‌خوان گیج می‌شود.
    • برای جدول‌های چیدمانی از این ویژگی‌ها سوءاستفاده نکن؛ table فقط برای دادهٔ جدولی است.
    thead, tbody, tfoot چه فایده‌ای دارند؟ساختار سه‌بخشی
    • سرستون‌ها در thead، داده‌ها در tbody و جمع‌بندی در tfoot می‌آید.
    • مرورگر می‌تواند هنگام چاپ، thead را در هر صفحه تکرار کند.
    • tfoot باید بعد از tbody در کد بیاید (نه اول جدول).
    • این سه تگ را می‌توانی با CSS جداگانه استایل بدهی.
    برای جدول بزرگ چه نکاتی هست؟قابل استفاده در موبایل
    • جدول را داخل ظرفی با overflow-x:auto بگذار تا در موبایل افقی اسکرول بخورد.
    • از border-collapse:collapse برای نبود فاصلهٔ دولایه استفاده کن.
    • برای سطرهای بلند، ارتفاع ثابت و text-overflow جایگزین حذف داده نکن.
    • همیشه یک نام بنویس؛ این بهترین توضیح برای کاربر صفحه‌خوان است.

    فلش‌کارت — ریزنکات این بخش

    alt را دقیقاً چطور بنویسم؟هدف تصویر را توصیف کن
    • فرمول: «چه چیزی + چه کاری/چه اطلاعاتی».
    • تصویر تزئینی: alt="" (خالی، ولی وجود دارد) تا صفحه‌خوان از آن بگذرد.
    • اگر تصویر لینک است، alt باید مقصد را بگوید، نه شکل تصویر.
    • نام فایل را در alt کپی نکن: «IMG_2034.jpg» بی‌معناست.
    چرا ابعاد تصویر را بنویسیم؟جلوگیری از پرش چیدمان
    • مرورگر قبل از بارگذاری تصویر نسبت ابعاد را می‌داند و جای خالی رزرو می‌کند.
    • این معیار CLS را در Core Web Vitals بهبود می‌دهد.
    • در CSS با aspect-ratio هم می‌توانی نسبت را تعیین کنی.
    • با object-fit: cover تصویر بدون کشیدگی پر می‌شود.
    srcset و sizes چه تفاوتی دارند؟انتخاب نسخه در مرورگر
    • srcset فهرست نسخه‌ها را با عرض واقعی (w) یا چگالی (x) می‌دهد.
    • sizes به مرورگر می‌گوید هر نسخه چقدر از صفحه را می‌گیرد.
    • با x برای صفحه‌های Retina مثل [email protected] 2x کار می‌کنی.
    • همیشه یک src پشتیبان داخل img بگذار.
    figure و picture چیست؟ظرف و سوییچ تصویر
    • figure ظرف مستقل تصویر/دیاگرام + figcaption است.
    • picture برای انتخاب نوع فایل (AVIF/WebP/JPG) یا آرت‌دایرکشن است.
    • در picture هم img نهایی الزامی است؛ مرورگرهای ناسازگار آن را نمایش می‌دهند.
    • برای تصویر تزئینی صرف، figure لازم نیست.

    اعتبارسنجی سمت مرورگر چه چیزهایی دارد؟required / pattern / min / max / step
    • required خالی‌بودن را می‌گیرد.
    • pattern الگوی regex را بررسی می‌کند، مثل کد ملی یا شمارهٔ تلفن.
    • minlength/maxlength طول متن و min/max مقدار عددی را کنترل می‌کند.
    • اعتبارسنجی HTML جایگزین اعتبارسنجی سرور نیست؛ حتماً سمت بک‌اند هم بررسی کن.
    چطور خطای فرم را دسترس‌پذیر کنم؟aria-invalid و aria-describedby
    • aria-invalid="true" را روی فیلد خطادار بگذار.
    • پیام خطا را در عنصری با id بگذار و با aria-describedby به فیلد وصل کن.
    • خطا را با متن بگو، نه فقط رنگ قرمز.
    • بعد از ارسال، تمرکز را به فیلد خطادار یا خلاصهٔ خطاها ببر.
    فیلدهای تخصصیbutton، datalist، output، progress
    • type="button" برای دکمه‌ای که فرم را ارسال نمی‌کند.
    • datalist فهرست پیشنهادی به input می‌دهد، بدون اجبار انتخاب.
    • output نتیجهٔ محاسبه را نشان می‌دهد و progress پیشرفت را.
    • type="file" با accept و multiple محدود و چندگانه می‌شود.
    امنیت فرمشماره‌های پشتی
    • روش POST برای دادهٔ حساس؛ GET داده را در URL لو می‌دهد.
    • autocomplete="off" روی فیلدهای حساس مثل کد یک‌بارمصرف.
    • توکن CSRF و محدودیت نرخ درخواست کار سرور است، نه HTML.
    • enctype="multipart/form-data" برای فرم همراه با فایل الزامی است.

    فلش‌کارت — ریزنکات این بخش

    script را کجا و چطور بنویسم؟classic و module
    • defer اسکریپت classic را بعد از parse اجرا می‌کند و ترتیب اسکریپت‌ها را حفظ می‌کند.
    • async به محض دانلود اجرا می‌شود و ترتیب تضمین نیست؛ برای اسکریپت مستقل analytics.
    • type="module" به‌صورت پیش‌فرض defer است و import/export دارد.
    • src خارجی را با integrity و crossorigin در صورت نیاز امن‌تر کن.
    template چه مزیتی دارد؟DOM inert و قابل clone
    • HTML داخل template در صفحهٔ اصلی رندر نمی‌شود.
    • با template.content.cloneNode(true) یک نمونهٔ قابل افزودن می‌سازی.
    • برای تکرار کارت‌های پروژه بدون چسباندن stringهای HTML مفید است.
    • هنوز باید دادهٔ کاربر را با textContent یا روش امن وارد کنی؛ template جلوی XSS را خودکار نمی‌گیرد.
    microdata یا JSON-LD؟دو روش دادهٔ ساخت‌یافته
    • microdata با itemscope/itemtype/itemprop داخل HTML قابل دیدن نوشته می‌شود.
    • JSON-LD بیرون از محتوای دیدنی و معمولاً خواناتر و قابل نگهداری‌تر است.
    • اطلاعات هر دو روش باید با محتوای صفحه همسان باشد.
    • برای پرتفولیو، JSON-LD Person ساده‌تر است؛ microdata را برای شناخت ساختار تگ‌ها یاد بگیر.

    فلش‌کارت — ریزنکات این بخش

    void element چیست؟تگ بدون closing tag
    • عناصر void محتوای فرزند ندارند: area، base، br، col، embed، hr، img، input، link، meta، source، track، wbr.
    • نوشتن <img></img> غلط/بی‌اثر است؛ همان <img ...> کافی است.
    • اسلش پایانی در HTML مثل <br /> الزامی نیست؛ فرم HTML را با XML قاطی نکن.
    • meta، link و input هم void هستند.
    Global attributes کدام‌اند؟ویژگی‌هایی که تقریباً همه‌جا می‌آیند
    • id، class، style، title، lang، dir، hidden، inert، tabindex، data-*، contenteditable، draggable، spellcheck، translate.
    • role، aria-* و slot/is برای سناریوهای ویژه‌اند؛ ARIA را جای semantic HTML نگذار.
    • accesskey را با احتیاط استفاده کن چون با میانبرهای سیستم و صفحه‌خوان تداخل دارد.
    • id یکتا، class برای گروه، data-* برای دادهٔ سفارشی DOM است.
    عناصر obsolete را بشناسم؟یادگیری برای تشخیص کد قدیمی
    • center، font، big، strike، tt، marquee، frame، frameset، noframes، acronym، dir و keygen را استفاده نکن.
    • ظاهر آن‌ها با CSS و ساختار آن‌ها با تگ معنایی جدید جایگزین می‌شود.
    • bgsound، blink، plaintext و xmp نیز legacy/obsolete هستند.
    • در مستندات ممکن است برای مهاجرت ببینی‌شان، نه برای ساخت پروژهٔ جدید.
    HTML parser چرا مهم است؟DOM واقعی همیشه عین متن نیست
    • مرورگر تگ‌های ناقص یا nesting نامعتبر را اصلاح می‌کند و ممکن است درخت DOM دیگری بسازد.
    • مثلاً قرار دادن block داخل p باعث بسته‌شدن ضمنی p می‌شود.
    • برای اشکال‌زدایی، Elements panel را با source متن یکی فرض نکن.
    • اعتبارسنجی با Nu HTML Checker یا ابزارهای lint کمک می‌کند.

    چک‌لیست دقیق پروژه

    قبل از اینکه بگویی تمرین تمام شده، این موارد را دستی آزمایش کن.

    • DOCTYPE، lang="fa"، dir="rtl" و UTF-8 درست هستند.
    • title، description، canonical و viewport نوشته شده‌اند.
    • یک h1، headingهای مرتب و sectionهای دارای عنوان دارم.
    • header/nav/main/footer و landmarkهای واقعی استفاده شده‌اند.
    • لینک‌های داخلی به id یکتا می‌رسند و متن لینک واضح است.
    • تصویر width/height و alt دارد؛ تصویر تزئینی alt خالی دارد.
    • جدول caption، thead/tbody/tfoot، th و scope دارد.
    • هر کنترل فرم label، name و type درست دارد.
    • فرم هم اعتبارسنجی HTML دارد هم قرار است سمت سرور بررسی شود.
    • صوت و ویدیو controls، fallback و track مناسب دارند.
    • با Tab، Enter و Space کل تعاملات کار می‌کنند.
    • focus دیده می‌شود و رنگ تنها راه اعلام وضعیت نیست.
    • انیمیشن در prefers-reduced-motion کاهش می‌یابد.
    • تگ‌های منسوخ مثل center، font، marquee و frame استفاده نشده‌اند.
    تمرین عملی نهایی: همین درس‌نامه را کنار بگذار و پرتفولیوی خودت را از صفر بساز. بعد با HTML validator، DevTools و Lighthouse آن را بررسی کن. فرق «دیدن کد» و «توانستن ساختن» همین‌جاست.
